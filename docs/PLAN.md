# 팀 허브 계획 (team.rescene-remine.com)

2026-10-19 사용자와 함께 정한 계획. 구현은 아래 단계별로 다른 세션이 한다. 각 세션은 이 파일을 먼저 읽고, 맡은 단계만 한다. 여기 적힌 결정은 다시 묻지 않는다. 여기 없는 결정이 생기면 사용자에게 묻는다.

## 1. 목표

리센느 음원총공팀 도구(분류기 등)를 한 곳에 모으고 로그인을 디스코드 하나로 통일한다.

- 허브 `team.rescene-remine.com`: 도구 목록, 내 프로필, 설정, 관리자. Cloudflare(Pages + Worker + D1 + R2)에 둔다. 홈서버가 죽어도 허브와 로그인은 산다.
- 도구는 지금처럼 홈서버의 서브도메인(`cert.`, `monitor.`, 앞으로 생길 분류기). 홈서버 앞의 문지기 `team-gate` 가 로그인을 확인한다.
- 모든 팀 사이트에 같은 헤더(로고, 도구 메뉴, 프사·닉네임, 설정, 로그아웃).
- 팀 비밀번호 로그인은 cert-sorter·monitor-dash 모두에서 없앤다. 예비로도 남기지 않는다.

같은 도메인 아래에 공개 사이트(`jachong.`, `showedup.`, `media.`)가 있다. 이 사이트들은 손대지 않고, 로그인 쿠키가 그쪽으로 가면 안 된다. 그래서 `.rescene-remine.com` 전체에 거는 공유 쿠키는 쓰지 않고, 사이트마다 따로 쿠키를 거는 리디렉션 방식으로 한다.

## 2. 구성

```
          ┌──────────── Cloudflare ─────────────┐
 브라우저 ─▶ team.rescene-remine.com              │
          │  Pages(화면) + Worker(로그인·API)    │
          │  D1(사용자·세션·설정) R2(멤버 사진)   │
          │  Worker 예약 작업(매일 역할 재확인)   │
          └───────┬─────────────────────▲───────┘
            서명된 표(리디렉션)       1분마다 동기화
                  ▼                      │
 브라우저 ─▶ 홈서버 Caddy ── forward_auth ─▶ team-gate (공개키만 가짐)
                  │
                  ├─▶ cert-sorter  (헤더로 사용자 받음)
                  └─▶ monitor-dash (헤더로 사용자 받음)
```

| 부분 | 위치 | 비고 |
|---|---|---|
| 허브 | GitHub `rescene-stream/team-hub` (새 저장소), wrangler 배포 | 커밋은 영어 Conventional Commits, Claude 공동 작성자 줄 없음, 주석은 짧은 영어(홈페이지 저장소 방식) |
| 문지기 | 이 저장소 `team-gate/` (Docker 컨테이너) | 이 계획서도 여기. 허브 저장소 첫 커밋에 같은 내용 복사 |
| 도구 | 기존 폴더 그대로 | |

## 3. 로그인

### 3.1 디스코드
- 앱: 기존 "리센느 음원총공팀" 앱 `1420078078511550657` 을 그대로 쓴다(monitor-dash 디코 로그인과 같은 앱). 돌아올 주소 `https://team.rescene-remine.com/auth/callback` 를 추가한다.
- 권한: `identify` + `guilds.members.read`. 사람 본인의 토큰으로 `GET /users/@me/guilds/{서버}/member` 를 읽어서 역할, 서버 닉네임, 서버 프사를 한 번에 얻는다. **봇 토큰을 Cloudflare 에 두지 않는다.**
- 서버 `1546419001041748068`, 들어올 수 있는 역할(총공팀) `1546422674035707944` (monitor-dash `config.json` 과 같은 값).
- 다시 오는 사람은 `prompt=none` 으로 승인 화면 없이 지나간다. 역할이 없던 사람이 다른 계정으로 다시 할 때만 `prompt=consent`(monitor-dash 방식).
- 역할 없음 → 들어올 수 없다는 화면(설명 문장 없이 짧게) + 다른 계정으로 로그인 버튼.

### 3.2 허브 세션
- `team.` 에만 쓰는 쿠키(`__Host-` 접두사, Secure, HttpOnly, SameSite=Lax). 30일.
- D1 `sessions` 에 세션 번호(sid)를 두고 로그아웃·강제 로그아웃 때 `revoked_at` 을 찍는다.
- 디스코드 refresh token 은 D1 에 Worker 비밀값으로 AES-GCM 암호화해서 저장한다(매일 재확인용).

### 3.3 도구로 들어가기 (리디렉션)
1. `cert.` 에 도구 쿠키가 없음 → Caddy `forward_auth` 로 물은 team-gate 가 `team./go?to=cert.rescene-remine.com&next=/원래경로` 로 보낸다. 이때 team-gate 는 state 값을 그 사이트 쿠키에 잠깐 넣는다(로그인 위조 방지).
2. 허브 로그인이 안 돼 있으면 디코 로그인부터. 돼 있으면 바로 3.
3. Worker 가 **도구 목록에 등록된 호스트에만** 표를 발급한다(아무 주소로나 보내지 않게). `next` 는 같은 사이트 안 경로만 허용한다.
4. 표: Ed25519 서명. 내용은 sid, 디코 번호, 받는 호스트(aud), state, 만료(발급 후 60초), 1회용 번호. 서명 키는 Worker 비밀값에만 있다.
5. `cert./_auth/callback?ticket=…` → team-gate 가 서명·호스트·state·만료·1회용을 확인하고 그 사이트 전용 도구 쿠키(7일, `__Host-`, HttpOnly, SameSite=Lax)를 건다 → `next` 로 보낸다.
- 도구 쿠키도 허브가 서명한 값으로 하고, team-gate 는 공개키로 확인만 한다(team-gate 는 아무것도 서명하지 않는다).

### 3.4 동기화, 로그아웃, 역할 재확인
- team-gate 는 1분마다 `team./api/gate/sync?since=…` 를 부른다(전용 토큰). 받는 것: 취소된 sid 목록, 바뀐 프로필(닉네임·프사·다크/라이트), 도구 목록.
- 허브가 응답하지 않으면 마지막으로 받은 값으로 계속 돈다.
- 어느 사이트 헤더에서 로그아웃해도 허브 세션이 취소되고, 1분 안에 모든 사이트에서 로그아웃된다.
- Worker 예약 작업이 하루에 한 번 세션이 살아 있는 모든 사람을 다시 확인한다(refresh token → member 조회).
  - 역할 없음·서버 나감·승인 취소 → 그 사람 세션 전부 취소.
  - 디스코드가 답하지 않음(5xx·시간 초과) → 이번엔 건너뛰고 다음 날 다시.
  - 닉네임·프사가 바뀌었으면 갱신(늦어도 하루 안에 반영).
- 도구 쿠키를 짧게 하지 않는 이유: cert-sorter 는 600MB 업로드를 받는데 도중에 만료되면 실패한다.

### 3.5 도구에 사용자 넘기기
- Caddy 는 `forward_auth` 응답의 `X-Team-User-Id`, `X-Team-User-Name`(UTF-8 퍼센트 인코딩)을 앱에 넘긴다.
- 방문자가 직접 보낸 같은 이름의 헤더는 Caddy 가 먼저 지운다.
- 앱은 이 헤더를 Caddy 에서 온 요청에서만 믿는다(4.2 monitor-dash 주의 참고).
- 각 도구 호스트의 `/_auth/*`(callback, me, logout)는 Caddy 가 team-gate 로 보낸다.

## 4. 기존 도구 옮기기

### 4.1 cert-sorter
- 로그인 화면, 팀 비밀번호(`TEAM_PASSWORD`), IP 잠금 코드, Caddy 의 `/login` 속도 제한 블록을 없앤다.
- 업로더 = 헤더의 디코 닉네임. 이름 입력칸과 "기기에 이름 저장"을 없앤다. `files` 에 디코 번호 칸을 추가하고, 닉네임은 **올린 시점 값**으로 저장한다. 나중에 닉네임을 바꿔도 옛 기록은 그대로다. 기존 기록은 그대로 둔다.
- `오늘 업로드` 는 닉네임별로 보여 준다.
- 공통 헤더를 붙인다. 다크/라이트는 아직 적용하지 않는다.
- **바꾸는 시점(사용자 결정: MAMA 투표 기간 중에 진행)**:
  - 팀원이 덜 쓰는 시간에 한다.
  - 시작 전에 `cert.db` 의 업로더 이름 목록을 뽑아 사용자에게 보여 주고, 모두 디코 총공팀 역할이 있는지 사용자가 확인한다.
  - 되돌리기를 준비해 둔다: 바꾸기 전 이미지 태그와 Caddyfile 사본. 되돌리기는 Caddyfile 복원 + 이전 이미지로 `up -d`. 판정 워커(`cert-sorter-worker`)는 건드리지 않는다(분류 중인 대기열 보호. README 의 `--no-deps web` 방식).

### 4.2 monitor-dash
- 자체 디코 로그인(`server/src/discord-login.ts`), 팀 비밀번호 로그인, 그 세션 쿠키를 없애고 team-gate 헤더로 바꾼다.
- **먼저 모든 경로를 인증 종류별로 목록으로 만든다.** 문지기 밖에 둬야 할 것:
  - `/internal/*`: 봇·별이 토큰 인증
  - dc gate 등 토큰을 쓰는 입구
  - 웹훅
- `/api/stream`(SSE)은 문지기 안에 둔다. 쿠키가 같이 간다.
- 주의 1: `media.rescene-remine.com` 도 같은 172.19.0.1:8092 로 간다. 공개 미디어 중계라 문지기를 걸지 않는다. 호스트로 구분된다는 점을 지킨다.
- 주의 2: monitor-dash 는 `network_mode: host`, 172.19.0.1:8092 로 듣는다. 이 다리 망의 다른 컨테이너도 X-Team-* 헤더를 보낼 수 있다. 이걸 막는 방법을 정해서 적용한다. 후보: Caddy 와 team-gate 가 공유한 비밀 헤더 하나를 더 넘기고 앱이 확인하기.
- 비밀 파일 `team-password.hash`, `discord-oauth.secret`, 디코 로그인 config 값을 정리하고 문서(DESIGN 18.3, HANDOFF)를 고친다.

## 5. 허브 기능

| 화면 | 내용 |
|---|---|
| 로그인 | 디코 로그인 버튼. 멤버 사진 |
| 메인 | 도구 카드(이름, 주소, 살아 있는지), 내 최애 사진(멤버별 여러 장 중 랜덤), 내 프사·닉네임 |
| 설정 | 최애 고르기, 다크/라이트 |
| 관리자 | 아래 표 |

관리자 화면:

| 항목 | 내용 |
|---|---|
| 접근 | 사용자 본인만. Worker 비밀값 `ADMIN_DISCORD_ID` 에 둔다. 번호는 1단계에서 사용자가 처음 로그인했을 때 D1 에서 읽어 넣는다 |
| 멤버·사진 | 멤버 추가·이름, 멤버별 사진 여러 장 올리기·지우기(R2) |
| 도구 목록 | 이름, 주소, 순서, 아이콘. 허브 카드와 헤더 메뉴와 표 발급 허용 목록이 이걸 쓴다 |
| 사용자 | 닉네임, 프사, 마지막 접속, 역할 확인 결과, 강제 로그아웃 |

- 도구가 살아 있는지: 각 도구의 `/_auth/health`(team-gate)를 Worker 가 확인한다. 1분 캐시.
- 도구별 역할 제한은 지금 만들지 않는다. 도구 목록에 나중에 칸을 붙일 수 있게만 둔다.
- 공지 배너, 즐겨찾기, 표시 이름 따로 정하기, 개인별 알림은 넣지 않는다(사용자가 고르지 않음).

### D1 (초안)
- `users`(디코 번호, 서버 닉네임, 프사 URL, 암호화한 refresh token, 역할 확인 결과·시각, 최애 멤버, 다크/라이트, 마지막 접속)
- `sessions`(sid, 디코 번호, 만든 시각, 만료, revoked_at)
- `tickets_used`(1회용 번호, 만료) — team-gate 쪽에서도 1회용을 막는다면 생략 가능
- `members`(번호, 이름, 순서), `member_photos`(번호, 멤버, R2 키)
- `tools`(호스트, 이름, 순서, 아이콘)

## 6. 공통 헤더
- `team./header.js` 웹 컴포넌트 `<team-header tool="cert">`. 도구 CSS 와 섞이지 않게 Shadow DOM 을 쓴다.
- 사이트마다 `<script>` 한 줄로 넣는다. 내용은 그 사이트의 `/_auth/me`(team-gate) 에서 받는다. 사이트끼리 쿠키를 나누지 않는다.
- 구성: 팀 로고(허브로) · 지금 도구 이름 · 도구 메뉴 · 프사+닉네임 → 설정(허브로) / 로그아웃.
- 허브가 죽어서 스크립트가 오지 않으면 헤더만 빠지고 도구는 그대로 돈다.
- 다크/라이트는 허브와 헤더에만 먼저 적용한다. 도구는 나중에 하나씩.
- 도구에 CSP 가 있으면 `script-src` 에 `team.rescene-remine.com` 을 넣는다.

## 7. 디자인

사용자의 말: "병맛보다는 지저분하지 않고, 정말 개발자가 재미로 만들었구나 하는 느낌." 사용자도 정확한 모양은 아직 모른다. 시안을 보고 정한다. **AI 같은 느낌은 극혐.**

- 대상은 허브 화면과 공통 헤더. 분류기 화면 자체는 지금처럼 수수하게 둔다(한눈에 읽히는 게 우선).
- 시안 여러 개를 한 페이지에 나란히 놓고 전환해서 고르게 한다. 고른 방향에서 다시 변형을 만든다.
- 리센느 멤버(센둥이) 사진이 들어간다. 시안용 사진은 2단계 시작 때 사용자에게 받는다.
- "재미로 만든" 느낌은 문구가 아니라 디테일로 낸다. 예: 사진 배치, 작은 이스터에그, 손맛 나는 요소, 콘솔 메시지.
- 지금까지 사용자가 싫다고 한 것(메모리 `ui-design-principles`):
  - 화면이나 동작을 설명하는 문장, 안심시키는 문장. 화면에는 라벨·데이터·짧은 동작어만.
  - 지어낸 순우리말 대신 흔한 말(로그인, 설정, 로그아웃, 닫기).
  - 글자 간격 넓힌 머리말(kicker), "A · B" 식 브랜드 짝, Noto Sans KR 굵은 글씨, IBM Plex.
  - 패널·배지·이모지가 많은 화면. 화면을 재배치하는 큰 움직임.
- 한글 글꼴은 Pretendard(홈페이지와 같음). 팀 정체성은 실제 팀 로고로.

## 8. 단계와 세션

| 단계 | 세션 | 내용 | 끝났다는 기준 |
|---|---|---|---|
| 1 | A | 허브 뼈대: 디코 로그인·역할 확인·프로필, 세션, D1, 표 발급, `/api/gate/sync`, 매일 재확인, 관리자 번호 지정. 화면은 임시 | 사용자가 로그인해서 자기 닉네임·프사가 보임. 역할 없는 계정은 막힘 |
| 2 | B | 디자인 시안 → 고르기 → 허브 화면, 헤더(`header.js`), 다크/라이트, 최애, 관리자 화면, R2 | 사용자가 시안을 골랐고 허브 전체가 그 디자인으로 돎 |
| 3 | C | team-gate 컨테이너, Caddy 연결, cert-sorter 옮기기(4.1) | 팀원이 디코로 cert 에 들어가 업로드하면 닉네임이 기록됨. 다른 사이트 로그아웃 1분 안에 cert 도 로그아웃 |
| 4 | D | monitor-dash 옮기기(4.2), 새 분류기 붙이는 법 문서(`team-gate/README.md`) | monitor 가 디코 하나로 돎. 봇·별이·미디어 중계 정상 |

- 1과 2는 동시에 해도 된다. 3은 1이 끝나야, 4는 3이 끝나야 한다.
- 각 세션 끝에 이 파일의 해당 단계에 "한 일 / 남은 일"을 적는다.

## 9. 사용자가 직접 하는 일

세션이 안내하면 사용자가 그 자리에서 직접 한다. 세션은 한 단계씩 안내하고, 사용자가 끝났다고 하면 다음으로 넘어간다. 비밀값은 사용자가 직접 넣는다(채팅에 붙여 넣게 하지 않는다. `wrangler secret put` 이나 비밀 파일로).

| 단계 | 할 일 |
|---|---|
| 1 | GitHub `rescene-stream/team-hub` 저장소 만들기 |
| 1 | Cloudflare: Pages 프로젝트, D1, `team.rescene-remine.com` 연결, Worker 비밀값(디코 client secret, 서명 키, 암호화 키, sync 토큰, 관리자 번호) |
| 1 | 디코 개발자 화면: 돌아올 주소 추가 |
| 2 | Cloudflare R2 버킷, 시안용 멤버 사진·팀 로고 전달 |
| 3 | 홈서버에 sync 토큰·공개키 파일 두기, 바꾸기 전 팀원 역할 확인, 바꾸는 시간 정하기 |
| 4 | 디코 개발자 화면: monitor 의 옛 돌아올 주소 지우기 |

## 10. 한도 확인 (무료)
- Worker: 요청당 CPU 10ms. Ed25519 서명·확인은 WebCrypto 로 충분하다. 하루 10만 요청이면 팀 규모에 넉넉하다.
- 예약 작업: 하루 1번. 사람 수만큼 디코를 부르니 member 엔드포인트 속도 제한을 지키며 천천히 돈다.
- D1, R2(10GB), Pages 모두 무료 범위.
