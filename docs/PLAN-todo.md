# 할 일 보드 계획 (team.rescene-remine.com/todo)

2026-10-20 사용자와 함께 정한 계획. 구현은 아래 단계별로 다른 세션이 한다. 각 세션은 이 파일과 `docs/PLAN.md`(허브 전체)를 먼저 읽고, 맡은 단계만 한다. 여기 적힌 결정은 다시 묻지 않는다. 여기 없는 결정이 생기면 사용자에게 묻는다.

## 1. 목표

노션의 팀 TODO 를 허브에서 **들어오자마자 내가(우리 팀이) 할 일이 보이게** 한다. 노션 참여율이 낮으니, 노션을 안 여는 팀원도 허브에서는 보게 만드는 것이 목적이다.

- 원본은 노션이다. 허브는 노션을 보기 좋게 보여 주고, **상태만** 바꿀 수 있다.
- 기준은 허브 2단계와 같다: 직관적, 한눈에, AI 같은 느낌 없음(`docs/PLAN.md` 7절, 메모리 `ui-design-principles`).

## 2. 노션 쪽 사실 (2026-10-20 API 로 확인)

- 항목 75개: 완료 11, 진행 중 30, 보류 31(대부분 `[근거 미확인] … 실행 대상 제외`), 시작 전 2, 제목 없는 빈 행 1.

- 같은 워크스페이스의 `총공일정` 데이터베이스는 이번에 쓰지 않는다(사용자 결정).

## 3. 구성

```
브라우저 ─▶ team.rescene-remine.com (Worker)
             /todo 화면 ── D1 todo_items (노션 사본)
                │              ▲
                │       1분 지난 사본이면 응답 뒤에 다시 받음
                │              │
                └── 상태 바꾸기 ─▶ api.notion.com (NOTION_TOKEN)
```

- 허브 Worker 안의 페이지다. 홈서버·team-gate·Caddy 는 손대지 않는다. 홈서버가 죽어도 돈다.
- 노션 토큰은 Worker 비밀값 `NOTION_TOKEN`. 데이터 소스 번호는 `wrangler.jsonc` 의 `vars.NOTION_TODO_SOURCE`.
- 화면은 지금 허브처럼 서버에서 HTML 을 만든다. 옆 창·묶음 전환·상태 바꾸기에만 작은 스크립트(`public/todo.js`).

## 4. 노션 사본 (읽기)

- D1 `todo_items` 에 정리한 값만 둔다(노션 응답 원본은 두지 않는다): page id, 제목, 상태, 작업 팀[], 담당자[], 분류, 마감(시작·끝·시각 있음 여부), 현재 단계, 다음 행동, 메모, 일정 근거, 시작일, 최초 확인일, 완료일, 허브 변경, 노션 URL, last_edited_time.
- `todo_meta`(한 줄): 마지막 동기화 시각, 마지막 실패 시각·이유, 작업 팀·담당자·상태 선택지(데이터 소스 스키마에서. 설정의 "내 팀" 목록과 이름 맞추기에 쓴다).
- 다시 받는 시점: `/todo` 나 홈을 열 때 사본이 1분보다 오래됐으면 지금 사본으로 먼저 보여 주고 `ctx.waitUntil` 로 다시 받는다(도구 상태 확인과 같은 방식). 두 요청이 동시에 받지 않게 `todo_meta` 에 "받는 중" 시각을 찍는다.
- 받을 때는 전부 받아 통째로 바꾼다(지워진 항목도 빠지게). 100개씩 페이지를 넘긴다. `filter_properties` 로 쓰는 속성만 받아 응답을 줄인다(무료 플랜 CPU 10ms).
- 제목이 빈 행은 버린다.
- 노션이 실패하면(토큰·권한·속성 이름 바뀜·5xx) 마지막 사본을 그대로 보여 주고 `todo_meta` 에 실패를 적는다. 화면에는 마지막 동기화 시각만 작게 보인다. 관리자 화면에 실패 이유를 보인다.

## 5. 상태 바꾸기 (쓰기)

- 누구나: 허브에 들어올 수 있는 사람 전부(총공팀 역할).
- 바꿀 수 있는 것: 상태 하나(시작 전·진행 중·보류·완료). 다른 칸은 노션에서.
- 완료로 바꿀 때 노션의 `완료일` 이 비어 있으면 오늘(KST) 날짜를 넣는다. 완료에서 되돌려도 완료일은 그대로 둔다.
- 바꾼 사람 기록:
  - 노션 TODO 에 rich_text 속성 **`허브 변경`** 을 새로 만든다(사용자가 노션에서 직접, 9절). 값은 마지막 한 번만: `센마인 10/20 14:03 진행 중→완료`. 노션에서도, 장부를 정리하는 AI 도 근거로 볼 수 있게.
  - 허브 D1 `todo_changes`(page id, 디코 번호, 그때 닉네임, 이전 상태, 새 상태, 시각)에 전부 남긴다. 옆 창에 최근 몇 개를 보인다.
- 순서: `POST /todo/status {page, from, to}` → Origin 확인(허브와 같게) → 노션에서 그 페이지를 읽어 지금 상태가 `from` 과 같은지 확인 → 다르면 바꾸지 않고 최신 값으로 화면을 고침 → 같으면 `PATCH /v1/pages/{id}`(상태, 완료일, 허브 변경) → D1 사본과 `todo_changes` 갱신.
- 노션에는 "연동 봇이 고침"으로 남는다. 누가 했는지는 `허브 변경` 칸이 대신한다.

## 6. 화면

### 6.1 `/todo` (시안 A2 확정, 2026-10-20)
시안: https://claude.ai/artifact/JNJQFBDd5a3pyEuVZu17Yt (비공개)

**머리말·요약 문장을 두지 않는다.** "지금 볼 것", "내 것", "담당 1 · 개발 3", "동기화 21:52" 같은 글자는 사용자가 AI 같은 가치 없는 글자라고 뺐다. 급한 것과 내 것은 배치·색·날짜로 드러낸다.

위에서 아래로:

1. 제목 "할 일" + 팀별/사람별 전환(`localStorage` 에 기억).
2. **마감 띠**: 일주일 전 ~ 4주 뒤 날짜 축. 마감 있는 진행 중·시작 전 항목을 그 날짜에 점 + D-day + 제목으로 찍는다(겹치면 줄을 나눈다). 오늘 이전 구간은 옅게 칠하고, 지난 것은 점·D-day 가 붉은색. 누르면 6.2 의 창.
3. **보드**: 작업 팀별 칸(내 팀 칸이 맨 앞, 그다음 SNS·총대·디자인·개발·분석·총무·기타·팀 없음). 사람별이면 담당자 칸(내가 맨 앞) + 담당 없음.
   - 칸 머리: 이름 + 개수만.
   - 칸 안에는 진행 중·시작 전만. 보류·완료는 칸 아래 접힌 줄("보류 4 · 완료 6")을 누르면 그 칸만 아래로 길어지며 흐린 카드로 나온다(옆 칸·띠는 움직이지 않음). 다시 누르면 접힌다. 완료는 최근 완료일 순.
   - 정렬: 마감 지남 → 마감 가까운 순 → 진행 중 → 시작 전, 같으면 최근에 고친 것 먼저.
   - 여러 팀·여러 담당자인 항목은 해당하는 칸마다 나온다.

카드: D-day(있으면, 지난 것은 붉게) · "시작 전"(그 상태일 때만), 제목, 현재 단계 두 줄, 담당자(팀별일 때, 있으면).

마지막 동기화 시각은 화면에 두지 않는다. 동기화 실패는 관리자 화면에서만 본다.

### 6.2 항목을 눌렀을 때
**붙는 작은 창(P5) + 표(D1)** 확정(2026-10-20).

- 창: 누른 카드(또는 마감 띠의 점) 바로 옆에 폭 380px 로 뜬다. 오른쪽에 자리가 없으면 왼쪽, 위아래는 화면 안으로 밀어 넣는다. 뒤를 어둡게 하지 않고, 바깥을 누르거나 Esc 나 닫기로 닫힌다. 다른 카드를 누르면 그 옆으로 옮겨 간다. 누른 카드는 테두리로 표시.
- 폰 폭(640px 미만)에서는 아래에서 올라오는 시트(높이 최대 72%, 뒤는 어둡게).
- 내용(위에서 아래로): 제목 + 닫기 → 상태 버튼 4개(시작 전·진행 중·보류·완료, 지금 상태가 채워짐) → 표(마감 "D-2 · 10/22 23:59", 작업 팀, 담당자, 분류, 완료일은 있을 때만) → 현재 단계 → 다음 행동(있을 때만) → 바꾼 기록(있을 때만, `센마인 · 10/20 14:03 · 진행 중 → 완료`) → 노션에서 열기.
- 상태를 누르면 바로 바뀐다(되묻지 않음). 완료·보류로 바꾸면 창은 그대로 두고 보드에서만 빠진다.

창 안에 들어갈 것: 제목, 상태 바꾸기, 작업 팀·담당자·분류, 마감·완료일, 현재 단계, 다음 행동, 바꾼 기록, 노션에서 열기. `메모` 는 `현재 단계` 와 같은 글이고 `일정 근거` 는 거의 모두 같은 문장이라 넣지 않는다(2026-10-20 데이터). 뒤의 보드는 움직이지 않는다. 주소에 `#항목번호` 를 붙여 링크로 공유할 수 있게 한다.

### 6.3 허브의 다른 곳
- 옆 메뉴: 홈 아래 "할 일".
- 옆 메뉴 "할 일" 옆에 마감 지난 개수를 붉은 숫자로(0 이면 없음).
- 홈: 도구 카드 위에 `/todo` 와 같은 **마감 띠**(머리말 없음). 점을 누르면 같은 작은 창. 다른 도구를 쓰러 왔다가도 보이게 하는 것이 목적이다. 숫자 요약 카드는 두지 않는다(사용자 결정).
- 도구 사이트 공통 헤더(`header.js`) 메뉴: 홈 아래 "할 일"(허브 `/todo` 로).
- 설정: **내 팀** 고르기(여러 개, 노션의 작업 팀 선택지). 고른 팀 칸이 보드 맨 앞에 온다. 사람별 보기에서는 내 칸(이름 짝으로 찾음)이 맨 앞.
- 관리자: 노션 동기화 상태(마지막 성공·실패 이유), **이름 짝**(노션 담당자 이름 ↔ 허브 사용자. 기본은 디코 서버 닉네임과 같으면 자동, 다르면 여기서 지정).

### 6.4 디자인
- 허브 차콜 테마, 다크/라이트. 화면에는 라벨·데이터·짧은 동작어만. 설명 문장, 안심 문장, 이모지, 배지 남발 없음.
- 마감 지남·임박은 색 하나로만 강조(큰 면 채우기 없이).
- 확정 시안의 소스: `docs/todo-mockup.html`(글꼴·로고·데이터는 `__FONT__` 등 자리표시자. 데이터 모양은 `DATA` 배열 참고). 화면은 여기서 클래스·간격·색을 그대로 가져간다.

## 7. D1 (초안)

```sql
CREATE TABLE todo_items (page_id TEXT PRIMARY KEY, title TEXT NOT NULL, status TEXT, teams TEXT NOT NULL,  -- JSON 배열
  assignees TEXT NOT NULL, category TEXT, due_start TEXT, due_end TEXT, stage TEXT, next_action TEXT,
  memo TEXT, basis TEXT, started TEXT, first_seen TEXT, done_on TEXT, hub_change TEXT, url TEXT NOT NULL,
  edited_at TEXT NOT NULL);
CREATE TABLE todo_meta (id INTEGER PRIMARY KEY CHECK (id = 1), synced_at INTEGER, syncing_at INTEGER,
  failed_at INTEGER, error TEXT, options TEXT);
CREATE TABLE todo_changes (id INTEGER PRIMARY KEY, page_id TEXT NOT NULL, user_id TEXT NOT NULL, user_name TEXT NOT NULL,
  from_status TEXT, to_status TEXT NOT NULL, at INTEGER NOT NULL);
CREATE TABLE todo_people (notion_name TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id));
ALTER TABLE users ADD COLUMN teams TEXT;  -- JSON 배열, 설정의 내 팀. updated_at 은 건드리지 않는다(team-gate sync 와 무관)
```

## 10. 알아 둘 것

- **데이터가 비면 보드도 빈다.** 담당자 11/75, 마감 8/75, 다음 행동 7/75. "할 일이 딱 보이게"는 장부에 이 칸들이 채워져야 완성된다. 장부는 다른 팀원이 AI 로 정리하는 것으로 보인다(사용자, 2026-10-20). 사용자가 그 팀원에게 아래 규칙을 전한다. 안 넣으면 정리 때 허브에서 바꾼 상태가 되돌려질 수 있다.
  - 담당자·마감일·다음 행동은 대화나 보고에 근거가 있으면 채운다. 담당자 이름은 디코 서버 닉네임 그대로.
  - `허브 변경` 칸에 적힌 상태 변경(누가·언제·무엇에서 무엇으로)은 팀원이 직접 한 확인으로 보고 근거로 인정한다. 그보다 오래된 근거로 상태를 되돌리지 않는다.
  - `허브 변경` 칸 자체는 고치거나 지우지 않는다.
- **누가 보는지**: 허브에 들어올 수 있는 사람 전부가 모든 항목(회계·송금 내용 포함)을 본다. 노션의 공개 범위와 다르면 사용자에게 다시 묻는다.
- 노션에서 열기는 노션 권한이 있는 사람만 열린다. 그래서 옆 창에 내용 전부를 보인다.
- 한도: 노션 평균 초당 3회. 사본은 1분에 한 번까지라 넉넉하다. Worker 호출당 외부 요청 50개(무료) → 항목 5000개까지 한 번에 받는다.
- 넣지 않는 것(이번 범위 밖): 총공일정, 디코 알림, 상태 외 칸 고치기, 새 항목 만들기, 팀별 열람 제한.
